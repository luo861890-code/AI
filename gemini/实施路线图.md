## 阶段 2 · 多比例尺与缩放（1~1.5 周）—— **用户的"最最最重要"**

> **必须在前端 Leaflet 侧做**，因为比例尺是**渲染时**才确定的，后端 PNG 路线根本满足不了"地图能缩放"。
> 仓库已有 80% 的基础设施（`map-lod.js` 五档 LOD + 载负量预算 + `map.js` 真比例尺解算），**只缺两个接点**。

### 2.1 道路线宽随比例尺连续变化
**现状**：`map.js:619/650/674/908/1017…` 全部用**固定** `style.weight`。
**做法**：
1. 后端在 style 里**额外下发**语义字段（不改现有字段，向后兼容）：
   ```json
   "style": { "weight": 2, "widthModel": { "kind": "true_ground_width",
                 "meters": 28, "class": "primary", "minPt": 0.6, "maxPt": 14 } }
   ```
2. 前端在 `renderMap` 里用**实时比例尺**算屏幕宽度：
   ```js
   // map.js 已有的 _computeScaleData 给出 m/px
   const mPerPx = d.meters / d.mpx;
   const pt = clamp(mPerPx * widthModel.meters * (72/25.4) , minPt, maxPt)
   ```
   —— 这就是哈基米公式 `w(S)=w_ref·(S_ref/S)^0.36` 的**物理正确版本**（直接用真实路幅米数换算，而非经验幂律）
3. 真实路幅表（来自哈基米 `REAL_ROAD_WIDTH_METERS`，需按《城市道路工程设计规范 CJJ37》校核）：
   `motorway 36m / primary 28m / secondary 18m / tertiary 10m / railway 14m / subway 12m`

**验收**：在 1:250万 / 1:40万 / 1:5万 三档截图，道路像素宽度单调递增且**与真实路幅成比例**；缩放平滑无跳变。

### 2.2 行政层级下钻（省 → 市 → 区 → 街道）
**做法**：
1. 后端新增接口 `GET /api/maps/{id}/admin-layer?bbox=...&scale=...`
   - 按**视口 bbox + 当前比例尺**决定返回哪一级政区
   - 层级表：`1:≥1,000,000` 省/市州 → `1:100,000~1,000,000` 市辖区 → `1:<100,000` 街道/园区
   - 数据源：`hubei_cities.geojson`(17) / `wuhan_districts.geojson`(13) /（街道层需新增数据）
2. 前端监听 `zoomend`/`moveend`，命中层级切换条件时**拉取并替换** `admin_polygons` 图层
3. 保留现有 `_lodVisible`（L133）五档规则，把"行政层级"作为**第六类** LOD 维度并入

**验收**：湖北视图只见 17 市州分隔 → 放大到武汉自动出现 13 区 → 再放大出现街道/园区；**每次切换 300ms 内完成**且无闪烁。

### 2.3 载负量随尺度控制（把哈基米的 Töpfer + 仓库的预算合并）
- 后端：`topfer_radical_law_count` 给出**理论上限**
- 前端：`_applyLoadControl` 的**实际预算**（300/800/2500/7000/∞）取二者较小
- 在**图例/状态栏**显示当前尺度的"保留要素数 / 理论上限"，作为**可展示的制图综合证据**（结题答辩加分项）

### 2.4 长江/汉江面状化
- 后端 `local_geo_service.py` 已有水系处理 → 扩展为**线转面**：按实测河宽（长江武汉段 1200~1800m、汉江 260~450m）缓冲，**面宽随比例尺设下限**（保证任何比例尺下面状可辨）
- 比例尺切换时**面宽同步重算**（小比例尺不塌成线）
- 严格用**米制投影**（EPSG:4547）缓冲，不能在经纬度空间缓冲

**验收**：1:250万 / 1:40万 / 1:5万 三档下长江均为**双岸线面状**，且宽度随比例尺合理变化。

## 阶段 3 · 对话增量修改（1~1.5 周）—— 让"用大模型改地图"真正生效

> 哈基米的 `MapSceneState` **结构是对的**（图层树 + 要素寻址 + 审计日志 + Undo），**缺的是接线**。
> 仓库已有 `modify_map()`（`agent_service.py:375`）+ `_parse_modification_with_llm`（L1221）+ 关键词兜底（L1352）——**在它上面加，不要重写**。

### 3.1 先建"可寻址要素索引"
- 每个要素在生成时绑定**稳定 ID**：`{layer_id}::{adcode|osm_id|name}::{idx}`
- 落到 `map_data.layers[].features[].properties.feature_id`
- 索引导出为 `map_data.feature_index`，供 LLM 精确寻址

### 3.2 让样式覆盖真正作用到渲染
- `MapSceneState` 的 `feature_style_overrides` / `class_scale_multipliers` / `hidden_feat_classes` **必须被渲染器读取**（这是哈基米 P0-3 的反面）
- 实现为一个**样式解算层**：
  ```
  最终样式 = 图层默认样式 ⊕ 分类级倍率 ⊕ 要素级覆盖 ⊕ 缩放自适应
  ```
- 前端 `map.js` 在 `renderMap` 里走这条解算链

### 3.3 六段式提示词编译器（并入 `task_parser.py`）
- 保留哈基米的**六段式格式**（对标用户给的 NYC Taxi 样例，格式很对）
- 但**替换其实现**：哈基米的 `analyze_user_intent` 只有几个关键词 if → 升级为
  1. 仓库已有 `SixDimParser`（空间/时间/尺度/主题/受众/符号法）→ **先用它**
  2. KG 检索（`kg_service.query_cartographic_decision`）→ 补**约束**（禁图层、必图层、配色策略、符号法）
  3. 工具链（`tool_registry.get_tools_for_decision`）→ 补**执行计划**
  4. 最后才用 LLM 补全自然语言 → 结构化
- 产出**结构化 `CartoTaskSpec`**，而不是一段提示词文本 → 直接驱动阶段 1 的 pipeline

### 3.4 对话修改闭环
```
用户追问
  → 六段式编译(3.3) → LLM 输出 MapDeltaPatch JSON（结构化，可校验）
  → JSON Schema 校验 + 地图学硬约束校验（禁改坐标、禁破四色、禁破 Z-Order）
  → 命中具体 feature_id / 图层 / 分类
  → 写入 MapSceneState + 存 Undo 快照
  → 样式解算层(3.2) 重算 → 前端局部重绘
  → 审计日志（用户原话 / 改了什么 / 依据 / 前后对比图）
```

**验收**（**必须用 md5/bbox 客观判定，不能靠肉眼**）：
- 改"武昌区颜色" → 渲染结果的**武昌区像素颜色确实变了**，其余区域**像素级不变**（差异掩膜 = 仅武昌区）
- 改"隐藏支路" → 支路图层要素数下降，`tertiary` 全部消失
- 改"放大到 1:5万" → `target_scale_denom` 与 `bbox` 同时更新，前端视口与比例尺条同步
- 连续 5 轮修改 → Undo 5 次回到初始（md5 一致）

### 3.5 LLM 网关
**不移植**哈基米的 `UnifiedLLMGateway`（仓库 `llm_service.py` 已有 5 provider + 流式 + 重试，更成熟）。只**补两样**：

## 阶段 4 · 整饰、导出与质量（1 周）

### 4.1 出版级整饰（修 P1-3 破图）
- 斑马图廓：**画在 axes 内部**（或用 `bbox_inches=None` + 固定画布），确保 4 边闭合
- 经纬网：分度带 + 度分秒标注（保留哈基米 `format_dms`）
- 图名框：主图名 + 副图名 + **审图号/编制单位/数据来源/成图日期**（GB/T 20257 要求）
- 比例尺：**4 段黑白交替**图形比例尺 + 数字比例尺 `1:xxx`（用 `map.js` 已有的 `_niceScale` 逻辑）
- 图例：分层（点/线/面）结构化，**符号预览必须与图面一致**
- 指北针：矢量双翼（哈基米实现可用）

### 4.2 真正的服务端导出
- **SVG**：`export_service.export_svg` 已有雏形 → 升级到含斑马图廓/经纬网/图名/图例/比例尺/编制说明
- **PNG**：`export_png` 目前是 1×1 占位 → 两条路
  - (a) 前端 `leaflet-image` 截图（仓库注释里已提过）—— 轻量、所见即所得
  - (b) 服务端 matplotlib 渲染 —— **仅用于出版级成图导出，不作为交互渲染器**
  → **推荐 (a) 为主 + (b) 为辅**：把哈基米的渲染器**降级为导出器**，正好发挥其"出版级整饰"强项，而不与 Leaflet 主流程冲突
- **PDF**：SVG → PDF（`cairosvg` 或 `reportlab`，后者已在依赖里）

### 4.3 质量评分体系升级
现在 `cartography_validator.py` 三轴 0-100（图层完整 .40 / 符号规范 .35 / 色彩和谐 .25）**只查静态区间**。
**接入阶段 0.2 的回归台**，加 4 个客观维度：
- 相邻政区同色对数 = 0
- 注记碰撞对数 = 0（可接受 ≤ 0.1%）
- 图廓闭合性 = 4/4 边
- 中文字体 missing-glyph = 0
- 载负量：在 Töpfer 理论上限内
→ **质量分从"自述"变成"实测"**，这是结题报告里最有说服力的图表。

### 5.3 微调 / 强化学习：**先做数据，不急着训**
- 哈基米 `fine_tuning_trainer.py` 只有 **3 条**种子样本，且 `compute_rlhf_carto_reward` 用 `get('topology_clean', True)` —— **默认 True 即"没检查算通过"**，奖励函数无鉴别力

  3. 奖励函数改为：`R = 0.30·Schema合规 + 0.25·拓扑洁净 + 0.25·载负量合规 + 0.20·实测质量分`
