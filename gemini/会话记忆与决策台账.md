## 3. 本次评审的实验结论（**证据等级：已复现**）

> 全部结论都用 `D:\AAA-student\Projects\test\gemini` 的代码 + `carto-agent\backend\data` 的**真实数据**跑出来，不是读代码猜的。

### 3.1 ❌ 严重：`repair_geometries()` 静默丢弃 12/17 个地市
`calibration/topology_calibrator.py:72` 对自相交的 MultiPolygon 调用 `make_valid()`，shapely 返回 **`GeometryCollection`**；紧接着 L76 的过滤 `geom_type.isin(["Polygon","MultiPolygon"])` 把它们**全部丢掉**。
```
输入 17 个地市 → make_valid 后 12 个变 GeometryCollection → 修复后只剩 5 个
```
**后果**：`admin_prov.png` 里湖北省只剩随州/恩施/黄石/鄂州/神农架 5 个色块，其余 12 个市**整块消失**，而接口照常 `status=success`。
**修复**：`make_valid` 后需 `shapely.geometry.collection_extract` 或 `gpd.GeoSeries(...).explode()` 再 `Polygon/MultiPolygon` 重组。

### 3.2 ❌ 严重：中文全是豆腐块 □□□（且静默）
`renderers/base_renderer.py:27-34` 的 `detect_cjk_font()` 用 `f.name in fm.fontManager.ttflist` 判断字体存在 —— 这是**缓存列表**，可能包含文件已不存在的字体条目。
实测：注入一条失效的 `WenQuanYi Micro Hei` 条目后 → 选中的字体无法解析 → **8 条 missing-glyph 警告** → 全部中文渲染成 □，而 `savefig` 仍成功。
**同一份代码同一台机器，第一次跑出豆腐块、第二次跑出正常中文**，正是因为 `~/.matplotlib/fontlist-v3.11.0.json` 在两次之间被重建。
**修复**：用 `fm.findfont(FontProperties(family=n), fallback_to_default=False, rebuild_if_missing=False)` 做**存在性校验**；且首选列表必须是 `Microsoft YaHei / SimHei / Noto Sans SC`（Windows 实际有的），哈基米原列表前三项全是 Linux 字体。

### 3.3 ❌ 严重：「对话增量修改」**完全不生效**
`conversational_edit/dialogue_editor.py` 把补丁写进 `feature_style_overrides` / `class_scale_multipliers` / `hidden_feat_classes`，但**全仓库没有任何渲染器读取这三个字段**（grep 确认：只有写、没有读）。
实测：输入"把武昌区改成暖橙色 #FDBA74，描边加粗到 1.8pt" → 补丁正确解析并写入 → 重新渲染的 PNG 与修改前 **md5 完全相同**（`14aad5e0…`）。
`hidden_feat_classes` 也实测为空（因为图层名不匹配 `roads_lines`）。

### 3.4 ❌ 严重：多比例尺 LOD 引擎是**孤儿**
`multiscale_lod/scale_lod_engine.py` 的 `MultiScaleLODEngine` **没有被任何渲染器调用**。`traffic_map.py:80-82` 直接取 `CartoSymbolLibrary.get_traffic_road_styles()` 的**固定**样式，不带比例尺参数。
实测：`1:2,500,000` 时 motorway 线宽 1.43pt，`1:50,000` 时 5.5pt（引擎算得出），但**渲染出来完全一样**。
`ScaleLevelSpec.admin_unit_level` 在其定义文件里出现 4 次，**没有一处被消费** → "省→市→区三级下钻"只停留在数据结构层面。

### 3.5 ❌ 严重：Töpfer 定律与「河流线转面」**从未被调用**
- `topfer_radical_law_count` → grep 全仓库，**零调用点**
- `river_centerline_to_polygon` → grep 全仓库，**零调用点**
- `clean_and_register_layer` → 零调用点
即"长江用面状表示"这个用户最在意的点，**代码写了但没接线**。

### 3.6 ❌ 中等：`terrain_map.py` 在真实数据上**崩溃**
`terrain_map.py:140` `int(row.get('elevation', 150))` —— 真实 `wuhan_peaks.geojson` 的 `ele` 字段存在**空字符串**，抛 `ValueError: invalid literal for int() with base 10: ''`。
另：`wuhan_contours.geojson` 用 `index`(0/1) + `ele` 表达计/首曲线，哈基米代码却按 `feat_class` 字段过滤 —— **字段契约不一致**。

### 3.7 ❌ 中等：`tourism_map.py` 图例数为 0
图层键名契约不一致：哈基米代码期望 `tourism_pois_points` / `tourism_routes_lines` / `greenspace_polygons`，而仓库数据是 `wuhan_tourism.geojson` / `wuhan_roads.geojson`（且**没有 greenspace 图层**）。实测 `legend_count=0`、`carto_score=55`。
→ **仓库与新模块之间缺少一层「图层适配器（Adapter）」**，这是哈基米"5 行代码即可接入"说法不成立的真正原因。

### 3.8 ❌ 中等：图廓斑马纹**画在了图廓外，且只有 3 边**
`map_elements.py:82/99` 用 `y_pos=-band_h` 和 `x_pos=-band_w`（**负值**）配合 `transform=ax.transAxes`，而 `savefig(bbox_inches="tight")` 又会把画布外的图元裁掉。
像素级实测：成品图 4 条边 6px 内的深色覆盖率**全部为 0.0%**；顶边只有 1 行有深色（28%），左/右/底边完全没有。且顶边那条黑带被图名框压住（zorder 100 > 99）。
→ 视觉上"有黑边"，实则**不是闭合图廓**，且与图名框打架。

### 3.9 ⚠️ 待定：「GCJ-02 偏移 300~500m」**在本仓库数据上不成立**
这是哈基米诊断的第一条，也是最响亮的一条，用数据检验后**部分证伪**：
- 栅格互相关（1424×699 @ ~40m）找 DataV 政区 vs OSM 路网最佳相对位移：重叠率 138366 → 141555（+2.3%），最佳位移 **-1544m E / -976m N**
- 边界顶点到最近 OSM 路线的距离中位数：**原始 115.3m → GCJ纠偏后 115.3m**（无改善），p90 574.7m → 512.2m（略好）
- 400 个 OSM 路点落在**任何**政区外的数量：原始 87 → 纠偏后 90（**变差**）
**结论**：本地 `wuhan_districts.geojson` 里的 DataV 边界**已接近 WGS-84**，真实问题是「DataV 权威边界与 OSM 路网各自精度不同导致的 100~600m 错位」，而**不是**火星坐标系整体偏移。**强行套 GCJ-02 纠偏反而会引入 ~500m 系统误差**。
→ 正确做法是**源级 CRS 标注 + 权威边界优先 + 拓扑捕捉对齐**，而不是"一律纠偏"。

## 4. 结论性判断（本次评审的核心结论）

1. **哈基米的"诊断"层（问题清单）质量高，"实现"层（代码）存在多处致命断链。** 八个问题里 ①④⑤⑦ 是真问题且仓库确实缺；②③⑥⑧ 部分成立但仓库已有部分能力（前端 `map-lod.js` 已有五档 LOD 与载负量预算、`export_svg` 已有整饰、地图已有双线道路符号）。
2. **`carto_engine` 不能整体替换现有制图模块**，因为：①它依赖 geopandas/matplotlib/pyproj，仓库**一个都没有**；②它走 matplotlib 静态出图，与仓库 **Leaflet 实时渲染 + 5 步 ReAct 流水线**是两条平行世界；③图层键名契约不匹配（§3.7）；④关键能力未接线（§3.3-3.5）。
3. **正确策略是"外科手术式移植"**：把 `carto_engine` 里**确实比仓库强、且能独立成立**的算法（Fisher-Jenks、四色邻接、Chaikin、注记避让、溯源报告、六段式提示词）**以纯函数形式**抽出来，接到仓库既有的 `map_service → Leaflet style JSON` 链路上；把**双线道路外壳等已被仓库覆盖**的部分丢弃。
4. **用户"最最最重要"的多比例尺需求，仓库其实比哈基米模块更接近可实现**：`map-lod.js` 已有五档 LOD 与载负量预算、`map.js` 已有真比例尺解算 `_computeScaleData`。**缺的是"路宽随比例尺变"和"行政层级下钻"两点**，且必须做在**前端 Leaflet 侧**（因为比例尺是渲染时才知道的），而不是在 Python 后端。
